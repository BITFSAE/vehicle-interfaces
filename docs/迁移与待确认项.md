# 迁移与待确认项

本页只记录尚未确认、不能直接作为正式接口发布的内容。确认后应通过独立 PR 修改正式协议，并从本页移除或标记完成。

## 新版 CANA、CANB、CANC

ECU 同学在 `CANRS485_G473/REFERENCE` 提供了新版 `Vehicle_CanA.dbc`、`Vehicle_CanB_V2.dbc` 和 `CANC.dbc`。本次检查确认新版 CANA 与原副本哈希一致；CANB_V2 修复了旧 `Vehicle_CanB(1).dbc` 的乱码，并新增轮胎温度、完整 GPS、方向盘、驾驶模式和 IMU 定义；CANC 为新增总线定义。

中央仓库采用这三份文件作为基线，其中 CANB 再合入 PDM 和 FanController 报文。发布首个稳定版本前仍需：

1. 由各发送节点负责人确认 DBC 与当前固件完全一致；
2. 用实车或台架原始帧验证新版 CANB 的 GPS/IMU/轮温字段；
3. 确认遥测 `MotionTelemetry` 与新版 GPS/IMU 的换算一致；
4. 确认 CANC 中整车厂来源报文的公开再发布权利。

## Proto 与 Nanopb 副本

旧工程中存在多份 `fsae_telemetry.proto` 和 `.options`。本仓库迁入当前服务器配置使用的版本作为唯一源；下游工程后续应记录本仓库 Commit/Release，并停止把本地副本称为正式源。

旧 `fsae_telemetry_v2.options` 没有对应的正式 `v2.proto`，本次不迁入。若仍有运行中的固件依赖它，需要先确认对应 Proto 与生成器版本。

## 厂家 DBC 与许可证

- 确认 CANA 中 AMK 定义是否允许在公开仓库再次分发；
- 确认本仓库采用的开源许可证；
- 在授权结论明确前，不发布 `v1.0.0`，也不加入新的厂家原始资料。

## MQTT 认证

计划关闭匿名连接并启用用户名/密码，必要时增加 TLS。正式实施时需另开 Issue，明确：

- Broker 认证方式和最低 TLS 版本；
- 设备凭据的写入、轮换、吊销和交接方式；
- Topic 级读写权限；
- 断线重连、认证失败和时钟异常行为；
- 服务器和 STM32 的兼容上线顺序。

本仓库只保存协议说明和脱敏示例，不保存实际地址或凭据。
