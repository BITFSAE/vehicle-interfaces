# CANB 整车接口

CANB 承载整车调试、显示、低压配电、风扇、BMS、ECU SOP、IVT-S 和充电机报文。正式字段以 [`Vehicle_CanB.dbc`](../can/Vehicle_CanB.dbc) 为机器可读来源。本文重点说明 BMS 相关接口，并给出其他节点的现有报文入口。

## 1. 总线约定

| 项目 | 约定 |
| --- | --- |
| 帧格式 | 经典 CAN 数据帧，不使用 CAN FD 和远程帧 |
| 正常位率 | 500 kbit/s |
| Legacy 充电位率 | 250 kbit/s；仅 Legacy 充电模式使用 |
| ID 类型 | 除 Legacy 充电机两个 29 bit 扩展 ID 外，当前均为 11 bit 标准 ID |
| 多字节顺序 | 各报文分别规定；SOP 和 IVT-S 为小端，BMS 包状态和 Legacy 为大端 |

CANB 切到 250 kbit/s 后，500 kbit/s 节点不能继续通信。整车正常运行和 Chroma 充电均使用 500 kbit/s。

## 2. 现有报文分区

CANB 除 BMS 外，当前 DBC 已包含以下报文。各节点负责人后续补充周期、超时、无效值和现场验证；现有字段先以 DBC 为准。

| ID | 发送节点 | 用途 |
| --- | --- | --- |
| `0x050`、`0x060..0x066` | Display | IMU 原始包、时间、加速度、角速度、姿态和磁场 |
| `0x067..0x06A`、`0x301` | Display | GPS 位置、速度、航向、信号、里程和圈速 |
| `0x071..0x074` | DATA_COLLECTION_INTEGRAL | 四轮胎温 |
| `0x305` | ECU | 数据记录状态 |
| `0x310` | Display | 驾驶模式请求 |
| `0x502..0x509` | ECU | ECU 调试数据 |
| `0x5A0..0x5A1` | PDM | 低压母线和低压电池支路 |
| `0x5A2..0x5A7` | FanController、ECU | 风扇状态、诊断、命令、应答和参数状态 |
| `0x700`、`0x784` | SteeringWheel | 方向盘面板和冗余驾驶模式 |

新增 ID 前先检查本表和 DBC，避免与现有节点冲突。

## 3. BMS 报文总表

| ID | 类型/DLC | 方向 | 周期/触发 | 用途 |
| --- | --- | --- | --- | --- |
| `0x4A0` | 标准/8 | BMS → ECU | 50 ms | SOP 电流和功率上限 |
| `0x4A3` | 标准/8 | BMS → ECU | 紧跟 `0x4A0` | SOP 状态、原因和 CRC |
| `0x4A4` | 标准/8 | ECU → BMS | ECU 周期发送或采用新限值后 | SOP 确认 |
| `0x4B0` | 标准/7 | BMS → ECU/数采 | 500 ms | 包状态 |
| `0x4B1` | 标准/8 | BMS → ECU/数采 | 500 ms，变化时补发 | 故障汇总 |
| `0x4B2` | 标准/8 | BMS → 数采 | 500 ms，变化时补发 | 32 项告警等级 |
| `0x512..0x519` | 标准/6 | IVT-S → BMS | IVT-S 周期发送 | 电流、电压、温度、功率、电荷和能量 |
| `0x401/0x402/0x404/0x405` | 标准/8 | Chroma → BMS | 充电反馈 | 电压、电流、保护和输出状态 |
| `0x490` | 标准/3 或 6 | BMS → Chroma | 命令触发 | 输出、目标值和反馈周期设置 |
| `0x491` | 标准/可变 | Chroma → BMS | 命令应答 | Chroma 命令结果 |
| `0x1806E5F4` | 扩展/5 | BMS → Legacy 充电机 | 充电时约 1 s | 充电请求 |
| `0x18FF50E5` | 扩展/至少 5 | Legacy 充电机 → BMS | 充电反馈 | 电压、电流和状态 |

`0x401` 和 `0x402` 只属于 Chroma 反馈。BMS 包状态、故障和告警固定使用 `0x4B0..0x4B2`。

## 4. BMS 包状态、故障和告警

### 4.1 包状态 `0x4B0`

| 字节 | 内容 |
| --- | --- |
| 0..1 | 包电压，大端 `uint16`，0.1 V |
| 2..3 | 包电流，大端 `int16`，0.1 A；充电为正，放电为负 |
| 4 | SOC，0..100% |
| 5 bit0 | 包电压有效 |
| 5 bit1 | 包电流有效 |
| 5 bit2 | SOC 有效 |
| 5 bit3 | 138 串单体电压完整 |
| 5 bit4 | 48 路温度完整 |
| 5 bit7..5 | 保留，当前为 0 |
| 6 bit7..4 | BMS 状态：2 自检、3 待机、4 预充、5 高压接通、7 故障保持 |
| 6 bit3..0 | 告警等级：0 正常、1 一级故障、2 二级告警 |

电压、电流或 SOC 的有效位为 0 时，对应数值不作为当前测量使用。

### 4.2 故障汇总 `0x4B1`

| 字节 | 内容 |
| --- | --- |
| 0 | 高 4 bit 为 BMS 状态，低 4 bit 为告警等级 |
| 1..4 | 大端 32 bit `fault_code` |
| 5 bit7 | 故障保持已锁存 |
| 5 bit6 | 故障输出已锁存 |
| 5 bit5 | 已收到故障复位请求 |
| 5 bit4 | Flash 写入错误 |
| 5 bit3 | 日志清除中 |
| 5 bit2 | 充电模式 |
| 5 bit1 | 充电机类型：0 Legacy，1 Chroma |
| 5 bit0 | 保留，当前为 0 |
| 6 bit5..0 | 从控 1..6 离线位 |
| 7 | 格式版本，当前为 2 |

`fault_code` bit0..31：单体过压、单体欠压、单体过温、单体低温、单体电压采样无效、温度采样无效、单体压差、温差、包总压过高、包总压过低、辅助外设异常、SOC 过低、充电持续过流、放电持续过流、充电瞬时过流（保留）、放电瞬时过流（保留）、从控数据不完整、预充失败、关键控制故障、包电压测量不一致、电流传感器无效、CAN 运行故障、安全回路中断、Chroma 测量失联、Chroma 命令失败、从控 1..6 离线、IVT U1 无效。

### 4.3 告警等级 `0x4B2`

`0x4B2` 与 `fault_code` 使用相同的 32 项顺序，每项占 2 bit：

```c
level = (data[index / 4] >> ((index % 4) * 2)) & 0x03;
```

0 表示未触发，1 表示一级故障，2 表示二级告警，3 保留。只需要故障位图的节点可以忽略 `0x4B2`；需要区分故障等级的数采应同时接收 `0x4B1` 和 `0x4B2`。

## 5. ECU SOP 接口

SOP 接口使用 500 kbit/s、标准帧和小端字段。

### 5.1 限值 `0x4A0`

| 字节 | 内容 |
| --- | --- |
| 0..1 | 放电电流上限，小端 `uint16`，0.1 A |
| 2..3 | 充电/回收电流上限，小端 `uint16`，0.1 A |
| 4..5 | 放电功率上限，小端 `uint16`，0.1 kW |
| 6..7 | 充电/回收功率上限，小端 `uint16`，0.1 kW |

某一方向的电流或功率上限为 0 时，ECU 禁止该方向动力。

### 5.2 状态 `0x4A3`

| 字节 | 内容 |
| --- | --- |
| 0 bit7..4 | 协议版本，当前为 1 |
| 0 bit3..0 | 会话计数，0..15 循环 |
| 1 bit0 | 限值有效 |
| 1 bit1 | 允许驱动 |
| 1 bit2 | 允许回收 |
| 1 bit3 | 过流干预已使某一方向归 0 |
| 1 bit4 | BMS 故障保持 |
| 1 bit5 | 要求 ECU 确认，当前为 1 |
| 1 bit6 | 本组限值降低或变为 0 |
| 1 bit7 | 保留 |
| 2 | BMS 状态 |
| 3..4 | `LimitReason`，小端 16 bit |
| 5 | `InputHealth` |
| 6 bit1..0 | 干预等级：0 正常、1 降额、2 过流归零、3 故障或准备下高压 |
| 6 bit2 | 放电限值因过流归零 |
| 6 bit3 | 回充限值因过流归零 |
| 6 bit4 | 尚未收到有效 ECU 确认 |
| 6 bit5 | ECU 确认在 500 ms 内 |
| 6 bit6 | 实测电流低于过流退出值 |
| 6 bit7 | 保留 |
| 7 | CRC-8/SAE-J1850 |

`LimitReason` bit0..15：最低单体限制放电、最高单体限制回充、高温限制放电、高温限制回充、低温限制回充、低 SOC 限制放电、高 SOC 限制回充、程序电流/功率上限、单体电压无效、温度无效、U1 无效、SOC 无效、IVT 电流无效、BMS 状态或故障禁止动力、放电过流归零、回充过流归零。

`InputHealth` bit0..7：单体帧完整、单体极值有效、温度帧完整、温度极值有效、U1 有效、SOC 有效、IVT 电流有效、全部 SOP 输入有效。

### 5.3 ECU 确认 `0x4A4`

| 字节 | 内容 |
| --- | --- |
| 0 bit7..4 | 协议版本，当前为 1 |
| 0 bit3..0 | ECU 已采用的会话计数 |
| 1 bit0 | 报文、版本、计数和 CRC 检查通过 |
| 1 bit1 | 已用于最终扭矩计算 |
| 1 bit2 | 正扭矩已为 0 |
| 1 bit3 | 负扭矩已为 0 |
| 1 bit4 | 驱动受 BMS 限制 |
| 1 bit5 | 回收受 BMS 限制 |
| 1 bit6 | ECU 因 SOP 超时进入零扭矩 |
| 1 bit7 | ECU 自身故障禁止动力 |
| 2..3 | 最终放电功率上限，小端，0.1 kW |
| 4..5 | 最终回收功率上限，小端，0.1 kW |
| 6 | 主要限制来源 |
| 7 | CRC-8/SAE-J1850 |

### 5.4 CRC 和计数

CRC-8/SAE-J1850 参数：多项式 `0x1D`，初值 `0xFF`，输入和输出不反射，结果异或 `0xFF`。

- `0x4A3` CRC 输入依次为 `04 A0`、完整 `0x4A0` 8 字节、`04 A3`、`0x4A3` Byte0..6。
- `0x4A4` CRC 输入依次为 `04 A4`、`0x4A4` Byte0..6。
- ID 字节高字节在前。

BMS 每 50 ms 发送一组 `0x4A0 + 0x4A3`。ECU 在 `0x4A4` 回填已采用的会话计数。BMS 接受最近一组及最多落后 3 个计数的确认；ECU 确认超过 500 ms 未更新时，SOP 确认状态过期。

## 6. IVT-S 结果帧

自有 IVT-S 使用 `0x512..0x519`，每帧 DLC=6：

| 字节 | 内容 |
| --- | --- |
| 0 | MUX |
| 1 bit3..0 | 消息计数，0..15 循环 |
| 1 bit7..4 | 结果状态 |
| 2..5 | 小端 `int32` 测量值 |

| ID | MUX | 单位 | 测量 |
| --- | ---: | --- | --- |
| `0x512` | `0x00` | mA | 电流 |
| `0x513` | `0x01` | mV | U1，电池包内侧总压 |
| `0x514` | `0x02` | mV | U2，DC-link 电压 |
| `0x515` | `0x03` | mV | U3 |
| `0x516` | `0x04` | 0.1 °C | IVT-S 温度 |
| `0x517` | `0x05` | W | 功率 |
| `0x518` | `0x06` | As | 电荷计数 |
| `0x519` | `0x07` | Wh | 能量计数 |

结果状态高 4 bit 中，bit2 表示 measurement error，bit3 表示 system error；任一位为 1 时，该帧测量无效。每个通道超时为约 360 ms。

这些结果 ID 由 IVT-S 配置决定。更换设备或修改 ID 后，同时更新设备配置、DBC、接收节点和测试。IVT-S 厂商配置命令不属于当前整车运行接口，本文不复制厂商内部参数表。

## 7. Chroma 充电接口

Chroma 使用 500 kbit/s。

### 7.1 反馈帧

| ID | 最小 DLC | 字段 |
| --- | ---: | --- |
| `0x401` | 7 | Byte3..6，小端 IEEE-754 float，电压 V |
| `0x402` | 7 | Byte3..6，小端 IEEE-754 float，电流 A |
| `0x404` | 7 | Byte3..6，小端 `uint32` 保护位；0 表示无保护 |
| `0x405` | 4 | Byte3 输出状态；0 表示关闭 |

四类反馈分别使用 500 ms 超时。DBC 按设备常用的 DLC=8 定义；接收方按上表最小 DLC 检查所需字段。

### 7.2 设置命令 `0x490`

Byte0 为命令码，Byte1 为 0。字节参数命令 DLC=3，参数在 Byte2；float 或 `uint32` 参数命令 DLC=6，参数在 Byte2..5，使用小端。

| 命令码 | 参数 | 含义 |
| ---: | --- | --- |
| `0x02` | byte | 输出开关：0 关闭，1 打开 |
| `0x04` | float，V | 输出电压 |
| `0x05` | float，A | 输出电流 |
| `0x10` | `uint32`，ms | 电压反馈周期 |
| `0x11` | `uint32`，ms | 电流反馈周期 |
| `0x13` | `uint32`，ms | 保护反馈周期 |
| `0x14` | `uint32`，ms | 输出状态反馈周期 |

当前四类反馈周期均设置为 100 ms。

### 7.3 命令应答 `0x491`

成功时 Byte0 为“命令码 + `0x40`”。失败时 Byte0=`0x7F`，Byte1 为失败命令码；DLC 足够时 Byte3 为失败状态。

## 8. Legacy 充电接口

Legacy 模式使用 250 kbit/s。

`0x1806E5F4` 为 BMS 请求：Byte0..1 电压大端 0.1 V，Byte2..3 电流大端 0.1 A，Byte4 为控制字；停止请求的前四字节为 0、Byte4 为 1。

`0x18FF50E5` 为充电机反馈：Byte0..1 电压、Byte2..3 电流、Byte4 状态，均按 Legacy 设备协议解释；BMS 要求 DLC 至少为 5，反馈超时为 500 ms。

## 9. 联调检查

1. 确认总线位率和 ID 类型；Legacy 扩展帧不能按标准帧解析。
2. 用正、负电流样例检查 `0x4B0` 的大端 `int16`。
3. 检查 `0x4A0/0x4A3/0x4A4` 的小端字段、会话计数和 CRC。
4. 检查 IVT-S 的 MUX、状态、计数、单位和有符号值。
5. 分别验证 Chroma 500 kbit/s 和 Legacy 250 kbit/s，确认切换后不再使用旧位率数据。
6. 在 CANB 满载测试中测量 BMS 50 ms/500 ms 报文的实际周期和丢帧率。
