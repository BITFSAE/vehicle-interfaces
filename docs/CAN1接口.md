# CAN1 BMS 接口

CAN1 连接 6 个 BMS 从控、自有 IVT-S、F405 主控和调试工具，位率为 500 kbit/s。正式接口以 [`Vehicle_Can1.dbc`](../can/Vehicle_Can1.dbc) 为机器可读来源；本文说明报文用途、时序、有效性和工具命令。

## 1. 通用约定

| 项目 | 约定 |
| --- | --- |
| 帧格式 | 经典 CAN 数据帧，不使用 CAN FD 和远程帧 |
| ID 类型 | 从控、主控和工具报文为 29 bit 扩展帧；IVT `0x512..0x519` 为 11 bit 标准帧 |
| 数据字节 | Byte0 是数据区第 1 字节 |
| 大端 `uint16` | `value = Byte0 << 8 \| Byte1` |
| 温度 | 原始值减 30 后为摄氏度；`0xFF` 表示无效 |
| 单体电压 | 小端 `uint16`，单位 mV；`0xFFFF` 表示无效 |

接收方按 ID 类型和 DLC 识别报文。周期帧超时后按无效处理；带有效位的测量还必须检查对应有效位。

## 3. 从控采样帧

### 3.1 单体电压

每个从控发送 6 帧，共 23 串：

| 帧号 | 字节 | 内容 |
| ---: | --- | --- |
| 0 | Byte0..1 | 保留 |
| 0 | Byte2..7 | 3 个小端 `uint16` 电压 |
| 1..5 | Byte0..7 | 每帧 4 个小端 `uint16` 电压 |

电压单位为 mV。`2101..5399 mV` 是有效模拟量；`≤2100 mV`、`≥5400 mV` 和 `0xFFFF` 表示采样线断开或无效。单体顺序和每个 ID 的字段名见 DBC。

### 3.2 温度

Byte0..7 对应该从控的 8 路温度。物理值为原始值减 30 °C，当前有效原始范围为 0..129，`0xFF` 表示无效。

主控正式固件对每一帧使用 350 ms 超时。一个从控的 6 帧电压和 1 帧温度都在超时内且内容有效时，该从控数据完整。

### 3.3 自有 IVT-S 结果帧

自有 IVT-S 接在 CAN1，使用 `0x512..0x519`，每帧 DLC=6。CANB 上的同 ID 不属于 F405 输入，也不属于遥测网关的 IVT 解析来源。

| 字节 | 内容 |
| --- | --- |
| 0 | MUX |
| 1 bit3..0 | 消息计数，0..15 循环 |
| 1 bit7..4 | 结果状态 |
| 2..5 | 小端 `int32` 测量值 |

| ID | MUX | 单位 | 测量 |
| --- | ---: | --- | --- |
| `0x512` | `0x00` | mA | 电流 |
| `0x513` | `0x01` | mV | U1，电池侧总压 |
| `0x514` | `0x02` | mV | U2，电池外侧/逆变器侧（Pre）总压 |
| `0x515` | `0x03` | mV | U3 |
| `0x516` | `0x04` | 0.1 °C | IVT-S 温度 |
| `0x517` | `0x05` | W | 功率 |
| `0x518` | `0x06` | As | 电荷计数 |
| `0x519` | `0x07` | Wh | 能量计数 |

结果状态高 4 位：bit0 为 OCS，bit1 为精度降低/测量错误，bit2 为 measurement error，bit3 为 system error；bit1..3 任一为 1 时测量无效。每个通道超时约 360 ms。

这些结果 ID 由自有 IVT-S 配置决定。更换设备或修改 ID 后，同时更新设备配置、DBC、接收节点和测试。IVT-S 厂商配置命令不属于当前整车运行接口。

## 4. 主控状态帧

### 4.1 包状态 `0x186050F4`

| 字节 | 内容 |
| --- | --- |
| 0..1 | 包电压，大端 `uint16`，0.1 V |
| 2..3 | 包电流，大端 `int16`，0.1 A；充电为正，放电为负 |
| 4 | SOC，0..100% |
| 5 bit0 | 包电压有效 |
| 5 bit1 | 包电流有效 |
| 5 bit2 | SOC 有效 |
| 5 bit3 | 138 串单体电压完整 |
| 5 bit4 | 48 路温度完整 |
| 5 bit7..5 | 保留，当前为 0 |
| 6 bit7..4 | BMS 状态：2 自检、3 待机、4 预充、5 高压接通、7 故障保持 |
| 6 bit3..0 | 告警等级：0 正常、1 一级故障、2 二级告警 |

Byte5 对应有效位为 0 时，电压、电流、SOC、极值和单体累加值不作为当前测量使用。

| 5 | 最低单体编号，0..137 |

`0x186250F4`：

| 字节 | 内容 |
| --- | --- |
| 0 | 最高温度，原始值减 30 后为 °C |
| 1 | 最低温度，原始值减 30 后为 °C |
| 2 | 最高温度编号，0..47 |
| 3 | 最低温度编号，0..47 |
| 4 | 目标占空比非 0：0 否，1 是 |
| 5 | 风扇目标占空比，0..100% |
| 6 | 风扇转速，单位 100 rpm；254 表示 25400 rpm 及以上 |

| 7 bit2 | 已检测到转速 |

Byte4..7 为风扇状态字段，可独立于温度极值使用。

`0x186E50F4` 提供电池箱风扇的完整运行状态；上电后每 100 ms 发送，停止时继续报告零占空比和零转速。CAN1 帧供查看，标定只使用 CANB：

| 字节 | 内容 |
| --- | --- |
| 0..1 | 转速，大端 `uint16`，1 rpm/LSB |
| 2..3 | 实际占空比，大端 `uint16`，0.1%/LSB |
| 4..5 | 当前生效的占空比上限，大端 `uint16`，0.1%/LSB |
| 6 bit1..0 | 模式：0 自动，1 手动，2 关闭 |
| 6 bit3..2 | 供电来源：0 低压或未识别，1 Chroma 35 W，2 高压接通/DCDC 70 W |
| 7 bit0..7 | 与 `0x186250F4` Byte7 相同的八个风扇状态位 |

自动控制、远程租约和标定流程以 [`CANB接口.md`](CANB接口.md#83-bms-电池箱风扇报文-0x5aa0x5ad) 为准。

`0x186750F4` Byte0..1 为 138 串单体电压累加值，大端，单位 0.1 V；仅 `0x186050F4` 单体电压完整位为 1 时使用。

### 4.3 均衡位图 `0x186450F4..0x186650F4`

三帧各 6 字节，共 18 字节位图。仅在固件包含均衡功能且均衡开关开启时约 250 ms 发送；当前没有 CAN 均衡启用命令。字节定义见 DBC，每字节与单体的对应关系待均衡板负责人确认。

### 4.6 SOP、运行配置和固件身份

`0x186A50F4` 为 CANB `0x4A0` 的 CAN1 镜像，本帧使用大端（CANB 正式接口使用小端）：

| 字节 | 内容 |
| --- | --- |
| 0..1 | 允许放电电流上限，大端 `uint16`，0.1 A |
| 2..3 | 允许充电/回收电流上限，大端 `uint16`，0.1 A |
| 4..5 | 允许放电功率上限，大端 `uint16`，0.1 kW |
| 6..7 | 允许充电/回收功率上限，大端 `uint16`，0.1 kW |

ECU 正式使用的 SOP 接口见 [`CANB接口.md`](CANB接口.md)。

`0x186B50F4`：

| 字节 | 内容 |
| --- | --- |
| 0 | 工具协议版本，当前为 5 |
| 1 bit0 | 电流方向：0 正常，1 反转 |
| 1 bit1 | 充电机类型：0 Legacy，1 Chroma |
| 1 bit2 | 固件包含均衡功能 |
| 1 bit3 | 均衡已开启 |
| 1 bit4 | Flash 在线 |
| 1 bit5 | 配置等待保存 |
| 1 bit6 | 电流方向等待保存 |
| 1 bit7 | RTC 有效 |
| 2..3 | 充电机反馈电压，大端，0.1 V |
| 4..5 | 充电机反馈电流，大端，0.1 A |
| 6 | 充电机状态；Legacy 为原厂状态字节，Chroma 为保护位非 0 即保护 |
| 7 bit7 | 充电反馈整体有效 |
| 7 bit6..3 | Chroma 电压、电流、保护、输出反馈分别有效 |
| 7 bit2..0 | Chroma 输出状态；0 表示关闭，Legacy 忽略 |

电流方向在没有有效Sector2记录时默认使用1（反转）；已有0或1记录时按保存值恢复。设置方向后，以Byte1 bit6清零为保存完成。

`0x186C50F4` Byte0 为协议版本；Byte1 bit1..0 为构建类型（0 Debug、1 Release、2 Debug-Bringup，3 为保留值，不对应当前固件分支），bit3..2 为充电机固件变体（0 运行时选择 Legacy/Chroma，1 Legacy 固定位率），bit7 为构建时 Git 工作区有未提交内容；Byte2..7 为大端 48 bit Git 短版本。Legacy 固定变体的 CANB 上电即使用 250 kbit/s，不接受运行时切换。

`0x186C51F4` Byte0 为协议版本，Byte1 为年份减 2000，Byte2 为月，Byte3 为日，Byte4..7 为 0。

`0x186D50F4`：

| 字节 | 内容 |
| --- | --- |
| 0 | 协议版本，当前为 5 |
| 1 bit7 | IVT 电流在线 |
| 1 bit6 | IVT 电流结果错误 |
| 1 bit5..0 | bit5 U1 ready、bit4 U2 ready、bit3 U3 在线、bit2 As 在线、bit1 W 在线、bit0 Wh 在线；1 表示就绪或在线 |
| 2 | SOC 来源：0 未确定、1 IVT As、2 软件安时积分、3 冻结 |
| 3 | 保留，当前为 0 |
| 4..7 | SOC 电流零偏，大端有符号 `int32`，mA |

### 4.7 故障和告警

`0x187650F4`：

| 字节 | 内容 |
| --- | --- |
| 0 | 高 4 bit 为 BMS 状态，低 4 bit 为当前告警等级 |
| 1..4 | 大端 32 bit `fault_code` |
| 5 bit7 | 故障保持已锁存 |
| 5 bit6 | 故障输出已锁存 |
| 5 bit5 | 已收到故障复位请求 |
| 5 bit4 | Flash 写入错误 |
| 5 bit3 | 日志清除中 |
| 5 bit2 | 充电模式 |
| 5 bit1 | 充电机类型：0 Legacy，1 Chroma |
| 5 bit0 | 保留，当前为 0 |
| 6 bit5..0 | 从控 1..6 离线位 |
| 7 | 格式版本，当前为 4；版本3的 fault bit22 是旧版外部安回事件，版本4起 bit22 保留并固定为0 |

`fault_code` bit0..31：

| bit | 故障 | bit | 故障 |
| ---: | --- | ---: | --- |
| 0 | 单体过压 | 16 | 从控数据不完整或过期 |
| 1 | 单体欠压 | 17 | 预充失败 |
| 2 | 单体过温 | 18 | 关键控制故障 |
| 3 | 单体低温 | 19 | 包电压测量不一致（单体累加与 U1 差值超限） |
| 4 | 单体电压采样无效 | 20 | 电流传感器无效（IVT 电流帧离线或状态异常） |
| 5 | 温度采样无效 | 21 | CAN 运行故障 |
| 6 | 单体压差过大 | 22 | 保留，当前固定为 0；外部安回事件见 `0x186950F4` Byte0 bit4 |
| 7 | 温差过大 | 23 | Chroma 测量失联（电压和电流反馈同时失联） |
| 8 | 包总压过高 | 24 | Chroma 命令失败 |
| 9 | 包总压过低 | 25..30 | 从控 1..6 离线 |
| 10 | 辅助外设异常，只上报二级 | 31 | IVT U1 无效（未收到、超时或结果异常） |
| 11 | SOC 过低 |  |  |
| 12 | 充电持续过流 |  |  |
| 13 | 放电持续过流 |  |  |
| 14 | 充电瞬时过流，保留 |  |  |
| 15 | 放电瞬时过流，保留 |  |  |

`0x187850F4` 是 32 项告警各自的当前等级状态帧，2 s 周期、告警变化时补发。除保留项 bit22 外，第 i 项（i=0..31）与 `0x187650F4` 的 `fault_code` bit i 一一对应：`fault_code` 只表示该故障是否触发，本帧每项 2 bit 表示触发后的严重程度：0 未触发、1 一级故障、2 二级告警、3 保留。一级故障会触发安全动作（置故障保持、断开高压继电器、输出 BMS 故障信号，需故障复位后恢复）；二级告警只提示、不立即断电，可升级的二级告警持续约 9 s 后进入故障保持。本帧是逐项明细；`0x186050F4` Byte6 低 4 bit 的“当前告警等级”是所有 32 项中的最高档位。放置方式：

```c
level = (data[index / 4] >> ((index % 4) * 2)) & 0x03;
```

0 表示未触发，1 表示一级故障，2 表示二级告警，3 保留。

`0x187750F4` 发送当前保存的告警阈值，2 s 周期：

| 字节 | 内容 | 默认值 |
| --- | --- | ---: |
| 0..1 | 单体过压阈值，大端 mV | 4300 |
| 2..3 | 单体欠压阈值，大端 mV | 3100 |
| 4 | 单体过温阈值，摄氏度加 30 编码 | 90（60 °C） |
| 5 | 单体低温阈值，摄氏度加 30 编码 | 30（0 °C） |

`0x187F50F4` Byte0..2 为 23 个告警动作开关位，Byte3 为格式版本 7。版本7起，从控未就绪和从控离线开关在所有状态下控制保护动作；位位置保持不变。动作开关为0时，原始检测、故障码和告警等级仍继续上报：

| 字节 | 位 | 开关 | 常用默认 |
| --- | ---: | --- | ---: |
| 0 | 7 | 单体过压 | 1 |
| 0 | 6 | 单体欠压 | 1 |
| 0 | 5 | 单体过温 | 1 |
| 0 | 4 | 单体低温 | 1 |
| 0 | 3 | 单体压差 | 1 |
| 0 | 2 | 温差 | 0 |

## 5. 工具命令

### 5.1 统一请求 `0x18A050F5`

所有请求固定 DLC=8。Byte0 高 4 bit 为协议版本 5，低 4 bit 为操作码；Byte1 为 0..255 循环的请求计数；保留字节发送 0。

| 操作码 | 操作 | Byte2..7 |
| ---: | --- | --- |
| `0x01` | 设置充电参数 | Byte2..3 电压，大端 0.1 V；Byte4..5 电流，大端 0.1 A |
| `0x02` | 设置告警阈值 | Byte2..3 过压 mV；Byte4..5 欠压 mV；Byte6 高温编码；Byte7 低温编码 |
| `0x03` | 设置告警开关 | Byte2..4 为 23 个开关位，布局与 `0x187F50F4` Byte0..2 相同 |
| `0x04` | 请求故障复位 | Byte2..4 固定为 `A5 5A 3C` |
| `0x05` | 设置电流方向 | Byte2：0 正常，1 反转 |
| `0x06` | RTC 校时 | 年减 2000、月、日、时、分、秒 |
| `0x0F` | 维护操作 | Byte2 为子操作，Byte3..7 为参数 |

维护子操作：

| 子操作 | 参数 | 返回内容 |
| ---: | --- | --- |
| `0x01` | 无 | 日志数量和 RAM 事件丢弃数 |
| `0x02` | Byte3..4 日志序号，大端 | 一条 16 字节记录，分 4 帧返回 |
| `0x03` | Byte3..5 固定 `C3 3C A5` | 请求清除日志 |
| `0x04` | Byte3：0 Legacy，1 Chroma | 设置充电机类型 |

设置类请求在自检、待机或故障保持状态处理；其他状态返回结果码 2。设置充电机类型还要求当前未充电且高压状态机空闲。故障复位只在故障保持状态接受，真正退出故障保持还要求实时故障已清除、HV_ACC 请求已释放；以 `0x186050F4`/`0x187650F4` 的 BMS 状态从 7 回到待机为准。请求方以应答结果为准，不以 CAN 发送成功作为命令成功。

### 5.2 统一应答 `0x18A650F4`

| 字节 | 内容 |
| --- | --- |
| 0 | 协议版本 5 |
| 1 | 请求计数 |
| 2 | 命令码；维护命令为 `0x80 \| 子操作` |
| 3 | 结果码 |
| 4 | 应答时 BMS 状态 |
| 5 bit0 | Flash 在线 |
| 5 bit1 | 配置等待保存 |
| 5 bit2 | 电流方向等待保存 |
| 5 bit3 | 日志清除中 |
| 5 bit4 | 故障日志等待写入 |
| 5 bit5 | 当前固件允许关闭基础保护 |
| 5 bit7..6 | 保留，当前为 0 |
| 6..7 | 大端命令详情 |

结果码：0 已接受/完成，1 已生效且等待保存，2 状态不允许，3 DLC 错误，4 版本错误，5 参数错误，6 确认码错误，7 Flash 不可用或读取失败，8 日志序号越界，9 日志操作忙，10 日志版本或 CRC 错误。

请求方同时核对 Byte1 请求计数和 Byte2 命令码。结果码 1 表示参数已经生效，保存完成以 `0x186B50F4` 对应待保存位清零为准。

### 5.3 RTC 和日志数据

RTC 应答 `0x18A450F4`：Byte0 为状态，Byte1 为请求计数，Byte2..7 为年减 2000、月、日、时、分、秒。状态 0 成功，1 DLC 错误，3 日期时间非法，4 RTC 未就绪，5 设置失败，6 版本错误，7 请求忙。应答 Byte2..7 是校时后主控读回的实际时间，可用于核对校时结果；Byte0 非 0 时时间字段不可用。

日志数据 `0x18A750F4`：Byte0 为版本 5，Byte1 为请求计数，Byte2 为类型。

| 类型 | Byte3..7 |
| ---: | --- |
| 1 | Byte3..4 日志数量，Byte5..6 RAM 事件丢弃数，Byte7 状态位 |
| 2 | Byte3 分片号 0..3，Byte4..7 为记录的连续 4 字节 |

读取记录时按分片号 0、1、2、3 拼成 16 字节，四帧使用同一个请求计数。

## 6. 使用和验证

CAN1 接收 IVT-S `0x512..0x519`，每个通道约 360 ms 未刷新即过期；CANB 上的同 ID 不属于 F405 输入。协议版本变化时，工具先读取 `0x186C50F4` 和 `0x186B50F4`，再按对应版本发送命令。

联调检查 36 帧单体电压和 6 帧温度映射、IVT 八通道、正负电流编码、有效位、故障格式版本、工具请求与应答配对、日志四分片顺序。
