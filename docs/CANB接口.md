# CANB 整车接口

CANB 承载整车调试、显示、低压配电、风扇、BMS、ECU SOP、赛会能量计和充电机报文。自有 IVT-S 已迁到 CAN1。正式字段以 [`Vehicle_CanB.dbc`](../can/Vehicle_CanB.dbc) 为机器可读来源；全部 ID 的归属和用途见 [`CAN_ID分配.md`](CAN_ID分配.md)。

> **确认状态约定：** 表格中的“状态”用于区分该报文由谁确认。`BMS 已确认` 表示 BMS 侧发送或接收行为已按代码确认；`ECU 待确认`、`节点待确认` 表示字段可能已按历史 DBC 合入，但发送节点或对应接收方尚未给出最终确认。未确认项不得作为联调通过依据，详见 [`迁移与待确认项.md`](迁移与待确认项.md)。

> **接收节点称谓：** 整车侧接收节点统一称为“遥测”（云端/车载遥测链路）和“HMI”（车手显示屏/人机交互显示）；不再使用“数采”作为节点名称。`Display` 表示现有显示/车手屏设备节点名，DBC 中仍可保留该节点名。

## 1. 总线约定

| 项目 | 约定 |
| --- | --- |
| 帧格式 | 经典 CAN 数据帧，不使用 CAN FD 和远程帧 |
| 正常位率 | 500 kbit/s |
| Legacy 充电位率 | 250 kbit/s；仅 Legacy 充电模式使用 |
| ID 类型 | 除 Legacy 充电机两个 29 bit 扩展 ID 外，当前均为 11 bit 标准 ID |
| 多字节顺序 | 各报文分别规定；SOP 为小端，赛会能量计、BMS 包状态和 Legacy 为大端 |

CANB 切到 250 kbit/s 后，500 kbit/s 节点不能继续通信。整车正常运行和 Chroma 充电均使用 500 kbit/s。

## 3. BMS 包状态、故障和告警

CANB 三帧与 CAN1 使用相同的数据格式，字段说明在 [`CAN1接口.md`](CAN1接口.md)：

| CANB | 对应 CAN1 | 字段定义 |
| --- | --- | --- |
| `0x4B0` | `0x186050F4` | [包状态](CAN1接口.md#41-包状态-0x186050f4) |
| `0x4B1` | `0x187650F4` | [故障汇总和 `fault_code`](CAN1接口.md#47-故障和告警) |
| `0x4B2` | `0x187850F4` | [32 项告警等级](CAN1接口.md#47-故障和告警) |

`0x4B0` 的电压、电流和 SOC 只在对应有效位为 1 时使用。需要区分故障等级的接收方同时接收 `0x4B1` 和 `0x4B2`；只需要故障位图时读取 `0x4B1`。

## 4. ECU SOP 接口

> **状态：报文布局已由 BMS 实现确认，ECU 侧处理策略仍为暂定方案。** ECU 最终采用哪种接收、限幅、扭矩换算和确认发送规则，必须由 ECU 负责人在 [`ECU_SOP实现确认.md`](ECU_SOP实现确认.md) 中填写确认，不能直接按本章内容认定已联调完成。

SOP 接口使用 500 kbit/s、标准帧和小端字段。

### 4.1 限值 `0x4A0`

| 字节 | 内容 |
| --- | --- |
| 0..1 | 放电电流上限，小端 `uint16`，0.1 A |
| 2..3 | 充电/回收电流上限，小端 `uint16`，0.1 A |
| 4..5 | 放电功率上限，小端 `uint16`，0.1 kW |
| 6..7 | 充电/回收功率上限，小端 `uint16`，0.1 kW |

某一方向的电流或功率上限为 0 时，ECU 禁止该方向动力。

### 4.2 状态 `0x4A3`

| 字节 | 内容 |
| --- | --- |
| 0 bit7..4 | 协议版本，当前为 1 |
| 0 bit3..0 | 会话计数，0..15 循环 |
| 1 bit0 | 限值有效 |
| 1 bit1 | 允许驱动 |
| 1 bit2 | 允许回收 |
| 1 bit3 | 过流干预已使某一方向归 0 |
| 1 bit4 | BMS 故障保持 |
| 1 bit5 | 要求 ECU 确认，当前为 1 |
| 1 bit6 | 本组限值降低或变为 0 |
| 1 bit7 | 保留 |
| 2 | BMS 状态：2 自检、3 待机、4 预充、5 高压接通、7 故障保持 |
| 3..4 | `LimitReason`，小端 16 bit |
| 5 | `InputHealth` |
| 6 bit1..0 | 干预等级：0 正常、1 降额、2 过流归零、3 故障或准备下高压 |
| 6 bit2 | 放电限值因过流归零 |
| 6 bit3 | 回充限值因过流归零 |
| 6 bit4 | 尚未收到新鲜 ECU 确认 |
| 6 bit5 | ECU 确认在 500 ms 内 |
| 6 bit6 | 实测电流低于过流退出值 |
| 6 bit7 | 保留 |
| 7 | CRC-8/SAE-J1850 |

`LimitReason` bit0..15：最低单体限制放电、最高单体限制回充、高温限制放电、高温限制回充、低温限制回充、低 SOC 限制放电、高 SOC 限制回充、程序电流/功率上限、单体电压无效、温度无效、U1 无效、SOC 无效、IVT 电流无效、BMS 状态或故障禁止动力、放电过流归零、回充过流归零。

`InputHealth` bit0..7：单体帧完整、单体极值有效、温度帧完整、温度极值有效、U1 有效、SOC 有效、IVT 电流有效、全部 SOP 输入有效。

### 4.3 ECU 确认 `0x4A4`

| 字节 | 内容 |
| --- | --- |
| 0 bit7..4 | 协议版本，当前为 1 |
| 0 bit3..0 | ECU 已采用的会话计数 |
| 1 bit0 | 报文、版本、计数和 CRC 检查通过 |
| 1 bit1 | 已用于最终扭矩计算 |
| 1 bit2 | 正扭矩已为 0 |
| 1 bit3 | 负扭矩已为 0 |
| 1 bit4 | 驱动受 BMS 限制 |
| 1 bit5 | 回收受 BMS 限制 |
| 1 bit6 | ECU 因 SOP 超时进入零扭矩 |
| 1 bit7 | ECU 自身故障禁止动力 |
| 2..3 | 最终放电功率上限，小端，0.1 kW |
| 4..5 | 最终回收功率上限，小端，0.1 kW |
| 6 | 主要限制来源 |
| 7 | CRC-8/SAE-J1850 |

`0x4A4` 只在非充电模式接受。确认超时只影响 SOP 诊断状态，不影响 BMS 故障和高压状态机判定。

### 4.4 CRC 和计数

CRC-8/SAE-J1850 参数：多项式 `0x1D`，初值 `0xFF`，输入和输出不反射，结果异或 `0xFF`。

- `0x4A3` CRC 输入依次为 `04 A0`、完整 `0x4A0` 8 字节、`04 A3`、`0x4A3` Byte0..6。
- `0x4A4` CRC 输入依次为 `04 A4`、`0x4A4` Byte0..6。
- ID 字节高字节在前。

BMS 仅在非充电模式下每 10 ms 发送一组 `0x4A0 + 0x4A3`；充电模式下不发送。ECU 在 `0x4A4` 回填已采用的会话计数。BMS 接受最近一组及最多落后 3 个计数的确认；ECU 确认超过 500 ms 未更新时，SOP 确认状态过期。模式切换（进入或退出充电）时会话计数重新从 0 开始，并清除旧的确认状态。

> ECU 侧当前暂定的接收超时、恢复条件、扭矩限制链、`0x4A4` 发送周期和 `Byte6` 枚举，见 [`ECU_SOP实现确认.md`](ECU_SOP实现确认.md)，待 ECU 最终确认。

## 5. 赛会能量计结果帧

赛会能量计只在比赛时安装，并与自有 IVT-S 独立采集和上报。默认采用 IVT 原厂 CAN 结果帧：`0x521` 电流、`0x522` U1 逆变器侧总压、`0x526` 功率、`0x528` Wh；每帧 DLC=6，Byte0 为 MUX，Byte1 高四位为状态、低四位为计数，Byte2..5 为 Motorola/大端有符号 int32。赛会设备只连接 U1，不使用 U2。

赛会也可能提供 FS Datalogger。其 `0x521/0x522/0x526/0x528` 结果帧与上述大端布局一致；额外的 `0x430` 状态帧可用于识别 FS 数据源。厂家原始 DBC 只保存在 `archive/`，正式运行字段已归并到 `Vehicle_CanB.dbc`。

功率帧和 Wh 帧可能不发送。接收端只在对应 CAN 帧新鲜时设置 Protobuf presence；STM32 不用电压和电流补算功率，也不积分 Wh。自有 IVT 的 CAN1 定义见 [`CAN1接口.md`](CAN1接口.md)。Grafana 应分别使用 `ivt_telemetry.*`（自有）与 `energy_meter.*`（赛会）作对比，不能按“当前生效来源”互相覆盖。

## 6. Chroma 充电接口

Chroma 使用 500 kbit/s。

当前面板节点基准 ID 为 `0x200`，六个报文由同一基准派生：反馈偏移为 `+1/+2/+4/+5`，命令和应答偏移为 `+0x90/+0x91`。更改面板 ID 时必须同时修改 F405 的 `BMS_CHROMA_NODE_BASE_STD_ID`、本 DBC、can-host 和遥测网关的 Chroma ID。`0x300` 当前不可直接使用，因为会派生出已占用的 `0x301`（GPS Speed）和 `0x305`（ECU 数据记录）；应先在 `CAN_ID分配.md` 选一个六个派生 ID 都空闲的基准。

### 6.1 反馈帧

| ID | 最小 DLC | 字段 |
| --- | ---: | --- |
| `0x201` | 7 | Byte3..6，小端 IEEE-754 float，电压 V |
| `0x202` | 7 | Byte3..6，小端 IEEE-754 float，电流 A |
| `0x204` | 7 | Byte3..6，小端 `uint32` 保护位；0 表示无保护 |
| `0x205` | 4 | Byte3 输出状态；0 表示关闭 |

四类反馈分别使用 500 ms 超时、分别判定新鲜度，不能用其他类别的帧代替；反馈必须来自当前充电会话。DBC 按设备常用的 DLC=8 定义；接收方按上表最小 DLC 检查所需字段。

### 6.2 设置命令 `0x290`

Byte0 为命令码，Byte1 为 0。字节参数命令 DLC=3，参数在 Byte2；float 或 `uint32` 参数命令 DLC=6，参数在 Byte2..5，使用小端。

| 命令码 | 参数 | 含义 |
| ---: | --- | --- |
| `0x02` | byte | 输出开关：0 关闭，1 打开 |
| `0x04` | float，V | 输出电压 |
| `0x05` | float，A | 输出电流；BMS 当前请求上限为 4.5 A |
| `0x10` | `uint32`，ms | 电压反馈周期 |
| `0x11` | `uint32`，ms | 电流反馈周期 |
| `0x13` | `uint32`，ms | 保护反馈周期 |
| `0x14` | `uint32`，ms | 输出状态反馈周期 |

当前四类反馈周期均设置为 500 ms，用于联调期间降低 CANB 负载。反馈新鲜度和保护帧超时仍为 500 ms，实物联调需确认发送抖动余量。

### 6.3 命令应答 `0x291`

成功时 Byte0 为“命令码 + `0x40`”。失败时 Byte0=`0x7F`，Byte1 为失败命令码；DLC 足够时 Byte3 为失败状态。

## 7. Legacy 充电接口

Legacy 模式使用 250 kbit/s。

`0x1806E5F4` 为 BMS 请求：Byte0..1 电压大端 0.1 V，Byte2..3 电流大端 0.1 A，Byte4 为控制字；停止请求的前四字节为 0、Byte4 为 1。

`0x18FF50E5` 为充电机反馈：Byte0..1 电压，大端 0.1 V；Byte2..3 电流，大端 0.1 A；Byte4 为状态。BMS 要求 DLC 至少为 5，反馈超时为 500 ms。

## 8. PDM 与风扇控制器接口

### 8.1 PDM 低压遥测 (`0x5A0/0x5A1`)

- 周期：100 ms（`0x5A0` 总线状态、`0x5A1` 电池支路状态）
- 字段布局：大端 Motorola 格式
  - 电压：`int16`，0.001 V/LSB，有效范围 -32.768..32.767 V，无效占位 `0x7FFF`
  - 电流：`int16`，0.01 A/LSB，有效范围 -327.68..327.67 A，无效占位 `0x7FFF`；正=电池放电/负载消耗，负=电池充电，已通过串口实测确认；更换分流电阻接线后必须复测并同步 FanController
  - 功率：`uint16`，0.1 W/LSB，有效范围 0..6553.5 W，无效占位 `0xFFFF`
  - 能量：`uint16`，0.01 Wh/LSB，有效范围 0..655.35 Wh，MCU 上电累计

### 8.2 风扇控制器报文 (`0x5A2..0x5A9`)

- `0x5A2`（风扇状态，100 ms）：三路转速（大端 `uint16`，RPM）及两路实测输出占空比（`uint8`，0..100%）。
- `0x5A3`（风扇诊断，500 ms）：故障位图、输入新鲜度标志、最高电机温度与最高控制器温度（大端 `int16`，0.1 ℃）、两路目标占空比。
- `0x5A4`（控制命令，事件/租约）：操作码、序列号、5 字节参数及 CRC-8/SAE-J1850。
- `0x5A5`（命令应答，事件触发）：应答操作码、序列号、执行结果、模式及当前占空比。
- `0x5A6/0x5A7`（策略状态，查询/修改后）：温控曲线与故障安全策略参数分页状态。
- `0x5A8`（功率与仲裁状态，100 ms）：供电状态（UNKNOWN/BATTERY/TRANSITION/DCDC_READY/LIMITED/DATA_FAULT）、限功率原因、两路独立热需求、受限目标、当前电流预算及预测总线电流。
- `0x5A9`（标定状态，标定会话非 INACTIVE 时 100 ms）：标定会话状态（INACTIVE/ACTIVE/ABORTED/COMPLETED）、中止原因、当前测试步骤、两路标定目标、租约剩余时间及参数版本。

## 9. 联调检查

1. 确认总线位率和 ID 类型；Legacy 扩展帧不能按标准帧解析。
2. 用正、负电流样例检查 `0x4B0` 的大端 `int16`。
3. 检查 `0x4A0/0x4A3/0x4A4` 的小端字段、会话计数和 CRC。
4. 检查 IVT-S 的 MUX、状态、计数、单位和有符号值。
5. 分别验证 Chroma 500 kbit/s 和 Legacy 250 kbit/s，确认切换后不再使用旧位率数据。
6. 在 CANB 满载测试中测量 BMS 10 ms/500 ms 报文的实际周期和丢帧率。
7. 由 ECU 负责人填写 [`ECU_SOP实现确认.md`](ECU_SOP实现确认.md)，确认后方可认为 SOP 联调完成。
8. 由 ECU、Display/遥测/HMI、PDM、FanController、方向盘和遥测负责人分别确认各自帧的 ID、DLC、周期和字节序后，才可进入首个稳定发布。
