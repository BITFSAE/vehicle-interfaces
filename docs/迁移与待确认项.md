## 2. ECU SOP 实现（发布前必须完成）

ECU 最终采用哪种 SOP 接收、限幅、扭矩换算和确认策略，必须由 ECU 负责人在 [`ECU_SOP实现确认.md`](ECU_SOP实现确认.md) 中填写。当前 [`CANB接口.md`](CANB接口.md) 第 4 章只是暂定方案。**ECU 需要结合误触发风险、恢复速度、四轮协调和 CAN 容量给出实际采用值，而不是确认“沿用暂定值”。**

待确认内容至少包括：

- `0x4A0/0x4A3` 是否按当前暂定的 10 ms 报文组接收；
- 只收到一帧、CRC 错误、版本错误、计数重复、跳号时的处理；
- `LimitsValid=0`、限值为 0、放电/回充过流时是否立即清零；
- 未收到有效报文组时的零扭矩判定和恢复策略；
- 最终限值链（BMS、车辆模式、ECU、AMK）如何取 min；
- 电流/功率如何换算成四轮扭矩，是否保持轮间分配；
- `0x4A4` 的实际发送周期和 Byte1/Byte6 枚举；
- 与 AMK 故障、模式切换、充电模式的交互；
- 各报文的处理优先级是否过高，是否会造成无关断动力或高负载；
- 当前暂定策略是否过严，是否存在误触发 0 动力的风险。

## 2.1 ECU 需要补充的文档

ECU 除提交 DBC 外，还需提交以下报文的说明文档（集中到 `docs/ECU报文说明.md` 或 ECU PR 中提供链接）：

- `0x305`：字段定义、单位、比例、有效范围、周期、发送/接收节点、异常处理；
- `0x502..0x509`：四轮映射、字段定义、单位、比例、诊断码、状态枚举、周期、发送/接收节点；
- `0x4A4`：发送周期/触发、字段定义、CRC、Byte1 和 Byte6 枚举、异常处理；
- 如有 CANA 或 CANC 报文，同样补充。

## 3. BMS CAN1 和 CANB（BMS 侧已确认项）

以下内容 BMS 侧已经按当前代码确认，但仍建议保存台架联调记录：

- CAN1 扩展 ID、从控电压/温度帧和 138 串/48 路采样；
- CAN1 自有 IVT-S `0x512..0x519` 小端结果；
- 赛会能量计 `0x52x` 大端结果；
- Chroma 500 kbit/s 和 Legacy 250 kbit/s 充电；
- `0x4B0..0x4B2` 包状态/故障/告警；
- SOP `0x4A0/0x4A3` 发送与 `0x4A4` 有效确认判定。
- 电池箱风扇 CANB `0x5AA..0x5AD`、CAN1 `0x186E50F4` 和 `0x186250F4` 扩展状态位。

## 4. 遥测认证

关闭 MQTT 匿名连接前确认：

- Broker 认证方式和最低 TLS 版本；
- 设备凭据的写入、轮换、吊销和交接方式；
- Topic 读写权限；
- 断线重连、认证失败和时钟异常处理；
- 服务器和 STM32 的上线顺序。

真实地址和凭据不进入本仓库。
